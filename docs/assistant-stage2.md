# 第二阶段：可控仿真自主巡田（数据源接入农业数据模块）

实施日期：2026-10-07～2026-10-08；2026-10-28 起巡田数据源改为读取农业数据模块（农业环境数据中心）所选大棚的实时监测数据。直接修改原项目，不建立备份或工作副本。

## 已实现的主线

首页“自主巡田”或巡田页选择大棚，点击“开始自主巡田”。新流程读取所选大棚的实时监测数据，自主执行：环境读取 → 风险判断 → 叶片演示 → 本地知识检索 → 管理建议与人工复核 → 报告保存。

| 步骤 | 实际工作 | 展示和能力边界 |
| --- | --- | --- |
| 读取环境 | 从农业数据模块读取所选大棚的实时湿度、温度、土壤湿度（`getRealtimeSnapshot`） | 数据来自农业环境数据中心（模拟传感器网络），不连接真实硬件 |
| 环境判断 | 比较所选大棚实时湿度与预警阈值 | 高湿提醒不是病害诊断；低于阈值不是健康证明 |
| 叶片演示 | 按实时风险状态选择预设视觉发现和本地 SVG | 自绘示意图，不是实拍，没有模型推理或置信度 |
| 知识检索 | 对本地人工整理的摘要实际进行关键词匹配 | 展示来源、摘要、核对日期及匹配度；不是完整RAG或外网实时搜索 |
| 建议与复核 | 根据所选大棚环境分支整理建议 | 不生成农药剂量，不调用设备控制；必须人工核实 |
| 保存报告 | 在一个数据库事务中保存报告、复核任务及完成状态 | 完成提示只在事务提交后出现，重试不重复写报告 |

默认标准流程约60秒：前五步各完成后留12秒展示证据，第六步保存完成后结束。界面区分“实际执行耗时”和“证据展示时间”；展示等待不冒充图像推理或外部工具调用。暂停时间、网络和数据库延迟不计入约60秒的展示预算。

## 大棚与数据来源

- 启动前从大棚列表选择目标大棚（复用农业数据模块的 `GET /api/greenhouses` 与 `GET /api/patrol-demo/greenhouses`，含内置演示棚与自定义棚）。
- 环境数据不再手动输入：湿度、温度、土壤湿度在启动时读取所选大棚的实时监测数据，数据来自农业环境数据中心（模拟传感器网络），随监测时间变化。
- 预警阈值可调。默认阈值85%；可调范围70～95%为演示设置，不是针对所有大棚的农业安全标准。
- 叶片演示随实时风险状态选择：所选大棚实时湿度达到阈值时使用黄斑叶片示意（`tomato-spots.svg`），否则使用常规叶片示意（`tomato-normal.svg`），两者均不是病害确诊。
- 巡田场景名称随所选大棚生成（如“常规巡田 · 1号番茄智慧大棚”）。
- SVG 来源：本项目代码自绘，`apps/web/public/demo/tomato-normal.svg`、`tomato-spots.svg`，非实拍、非训练集。没有复制第三方病害照片。后续应引入许可和来源明确的真实样本，并由第五阶段用真实诊断服务替换视觉预设。

本地知识采用人工写作的简短摘要，不复制完整网页。来源核对日期2026-10-07：

1. [明尼苏达大学推广：Tomato leaf mold](https://extension.umn.edu/agriculture/specialty-crops/vegetable-farming/disease-management/tomato-leaf-mold)：高湿条件、叶片正反面症状和现场复核；资料说明低于85%也可能发病。
2. [宾夕法尼亚州立大学推广：Managing Leaf Mold in High Tunnels](https://extension.psu.edu/managing-leaf-mold-in-high-tunnels)：空气流动与高棚通风管理方向。网页直接访问可能限制，但核对到了公开索引正文。
3. [明尼苏达大学推广：Tomato leaf spot diseases](https://extension.umn.edu/garden-and-home/yard-and-garden/gardening-in-minnesota/yard-and-garden-problems/tomato-leaf-spot-diseases)：叶面水分、灌溉与空气流动。

知识包独立于用户上传的原有知识库，保证无外网时展示主线可运行。原有知识库和问诊功能没有被替换。引用原网页需要联网，报告中的本地摘要离线可读；没有可靠本地命中时停止建议步骤，不编造来源。

## 控制与恢复

- 同一账号一次只能保留一个未结束的新巡田任务。重复启动使用同一请求标识，同一标识始终返回原任务，包括完成后的重试。
- 暂停保留已完成证据及剩余展示时间；继续不会重新执行已完成步骤。
- 取消在当前本地操作安全完成后的串行边界生效。报告提交完成后任务不可取消；未进入保存提交的取消任务不写报告。
- 失败显示具体步骤，可“重试失败步骤”；已完成证据保留。保存失败时报告和复核任务一起回滚。
- 复位只清空当前界面展示并恢复默认大棚选择（列表第一个），不删除已保存报告、任务记录或人工复核记录。
- 后端负责执行，前端每秒左右同步状态。切页面、刷新浏览器、退出账号不会撤销已经启动的服务器任务；重新登录本人账号可恢复状态。
- 后端重启后未结束的运行任务安全暂停，用户点击继续才恢复，避免自动产生未经观察的写入。
- 同步失败时提示“服务可能仍在执行”，可手动同步，不将通信错误误当作任务取消。
- 原有上传巡田入口仍保留在展开区域，明确标注原模拟能力，不给用户上传图片套用大棚监测状态的预设诊断。

## 数据与权限

新增 `patrol_demo_runs` 表，只做加表迁移；原有业务记录不清空。任务快照包含输入大棚、步骤时间、证据、资料、建议和报告编号。

最终报告继续进入 `patrol_records`；复核任务进入现有 `warnings`，类型为 `patrol_demo_review`。内置演示大棚（`demo-*`）首次保存时建立 `simulation-<大棚id>` 的独立虚拟棚，避免把演示关联到真实地块；数据库中的自定义大棚直接关联原大棚记录。不会创建真实传感器或设备。

运行任务及复核操作严格限制为本人账号。管理员沿用原有历史报告可见范围，但不能更改其他账号的复核状态。历史记录展开后展示完整证据；只有明确勾选已逐项人工核实，才允许标记复核完成，完成不意味着病害确诊。

## 运行与复测

正式运行仍用 `npm run dev`；已生成 Prisma 客户端并执行新增迁移。换一份部署环境时先执行 `npm run db:generate` 和 `npm run db:migrate`，再启动。

工程检查：`npm run typecheck`、`npm run lint`、`npm run build`。

服务测试：`npm run test:patrol-demo`。脚本新建临时 SQLite，按迁移 SQL 初始化，再测试实际协调器和持久化；显式禁用外部 fetch。不会加载 .env、复制业务库或访问原数据库。

UI 隔离验证：先构建，再运行 `node scripts/stage2-ui-fixture.mjs`，访问 `http://localhost:4175`。使用页面列出的公开测试账号；实际新巡田路由、协调器、认证和报告存储连接独立临时库，其他业务接口是界面测试数据。这不是正式运行入口。

自动测试覆盖：请求去重、并发启动保护、暂停/继续/取消、实时大棚数据与阈值分支、按大棚生成场景、视觉随风险状态、本地知识、账号隔离、历史证据、人工复核、重启恢复、缺失资料失败与重试、事务失败回滚、保存重试和额外连续五轮巡田。其推进使用零展示等待，不能代替浏览器中标准时长体验。

浏览器工程验收和用户体验反馈在 `todo.md` 中记录。实际浏览器验证使用 computer-use 技能；未测试真实硬件、语音、训练模型或完整原有业务系统回归。

工程检查和服务测试均通过。桌面浏览器验证了高湿流程暂停、刷新恢复、跨页面继续、保存及历史复核状态持久化；另一轮常规巡查未暂停，从任务创建到报告保存结束约60.25秒。实际执行耗时来自步骤时间戳，12秒展示等待独立标注。连续五轮目前是服务自动测试，不是五轮完整浏览器或资源压测。新增面板窄屏复测仍留阶段6。

## 已知限制

- 当前是服务端状态机协调与关键词检索，不是大模型自由规划，不能宣称已实现真实无人巡田或病害诊断。
- 尚无真实图像推理、五音口型、完整情绪形变和新声音。这些仍按后续阶段实施。
- 原有 Agent 聊天工具和上传巡田仍可能使用旧模拟逻辑，新流程不把它们作为真实识别能力。
- 后端调度器按单个服务进程设计，未实现多实例分布式锁；不要同时启动多个API进程连接同一业务库。重启后恢复需要手动继续。
- 未做长期负载、GPU推理并发和真实现场压测；Three.js大块提示仍在。
- Node24的内置SQLite仅用于测试脚本，运行会显示实验特性提示；正式服务继续使用Prisma。
