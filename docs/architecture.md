# 架构说明

## MVP边界

第一阶段只搭建可运行的产品基础框架，核心能力以模拟数据和占位服务实现，保证后续可以逐步替换为真实服务。

## 系统分层

### 前端应用 `apps/web`

- 数字人工作台
- AI农业问诊页
- AI巡田页
- 农业数据页
- 农产品管理页
- 历史记录页
- 系统设置页

### 后端服务 `apps/api`

- `/api/health`：健康检查
- `/api/auth/*`：登录、当前账号和密码修改
- `/api/agriculture-data/current`：农业环境数据
- `/api/diagnosis`：AI问诊接口
- `/api/patrols`：AI巡田接口
- `/api/products`：农产品管理接口
- `/api/devices`、`/api/device-commands`：设备查看、管理员控制和审计
- `/api/agent/chat`：数字人 Agent 对话接口
- `/api/knowledge/*`：农业知识库上传、检索、RAG回答和检索日志接口

### 共享包 `packages/shared`

用于维护前后端共同依赖的数据类型、枚举和模块定义。

### 权限边界

除健康检查和登录外，业务接口均验证签名登录凭证。管理员拥有知识库维护、设备控制和全量业务记录权限；普通用户只能维护和查看自己的业务记录，设备仅可查看。

## 后续替换点

- 模拟农业数据 -> IoT平台或时序数据库
- 占位视觉分析 -> 多模态大模型或病虫害识别模型
- 简单 Agent 路由 -> 工具调用式 AI Agent
- 本地上传文件 -> 对象存储
- 模拟传感器时序数据 -> 数据库或 IoT 平台
- 本地确定性 Embedding -> 真实 Embedding 模型和向量数据库
